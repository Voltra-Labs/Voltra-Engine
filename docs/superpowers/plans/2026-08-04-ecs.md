# In-house ECS Implementation Plan

**Goal:** A minimal entity-component store with generational handles and zero
`unsafe`, good enough to hold a scene and iterate it.

**Architecture:** Generational `Entity` handles from a free-list allocator. One
sparse set per component type, kept in a `TypeId`-keyed map and reached through
safe `Any` downcasts. Queries iterate a component's dense array and look up the
rest by entity.

**Tech Stack:** Rust std only. No `bevy_ecs`, no `hecs`, no `unsafe`.

## Global Constraints

- New crate `crates/voltra-ecs`, no dependencies at all.
- No `unsafe` anywhere. If a design needs it, the design is wrong for now.
- `cargo clippy --workspace --all-targets -- -D warnings` stays clean.
- TDD: every step is a failing test first, verified failing before implementing.

---

## Why a sparse set and not archetypes

Archetypes give faster iteration by grouping entities with identical component
sets into contiguous tables. In Rust that needs `UnsafeCell`, `TypeId` erasure
over raw pointers, and a hand-proved aliasing argument in every query — a
subproject, not a module.

A sparse set gives O(1) insert, remove and lookup, and dense contiguous
iteration per component type. Its weakness is multi-component queries, which
degrade to a lookup per candidate. That is the right trade until a profiler
disagrees.

## File structure

| File | Responsibility |
| --- | --- |
| `entity.rs` | `Entity` handle and `Entities` allocator |
| `storage.rs` | `SparseSet<T>`: dense component storage for one type |
| `world.rs` | `World`: ties the allocator to the type-erased storages |
| `lib.rs` | Module declarations and re-exports |

## Tasks

### Task 1 — `Entity` and the allocator

Generation counters are the whole point: reusing an index without bumping a
generation means a stale handle silently addresses a new entity.

- Spawn returns increasing indices while none are free.
- Despawn returns the index to a free list and bumps its generation.
- A handle held across despawn/respawn must report as dead.

### Task 2 — `SparseSet<T>`

- `insert` returns the previous value, `get`/`get_mut`/`remove` by entity index.
- `remove` uses swap-remove and repairs the sparse index of the moved element —
  the classic bug here is forgetting that repair.
- Iteration yields `(Entity, &T)` over the dense array.

### Task 3 — `World`

- `spawn`, `despawn`, `is_alive` delegating to `Entities`.
- `insert`/`get`/`get_mut`/`remove` per component type, creating storage lazily.
- Despawn must drop the entity's components, or memory leaks per dead entity.
- Stale handles must not read a recycled entity's components.

### Task 4 — Queries

- `query::<T>()` over one component type.
- `query2::<A, B>()` iterating the smaller set and looking the other up.

### Task 5 — Wire into the workspace

Add to workspace members, re-export from `lib.rs`, document in ARCHITECTURE.md.
